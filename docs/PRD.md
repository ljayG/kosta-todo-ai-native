## 1. 배경과 목적

현재 My ToDo는 React 상태로만 동작하는 프론트엔드입니다. 새로고침하면 데이터가 사라집니다. 이번 버전(v1)의 목표는 다음과 같습니다.

1. 지금 화면에서 제공하는 기능을 요구사항으로 확정합니다.
2. FastAPI와 Supabase로 데이터를 서버에 저장합니다.
3. Vercel에 배포합니다.

## 2. 사용자와 사용 상황

- **사용자:** 하루 할 일을 관리하는 개인 1명.
- **주요 상황:** 아침에 오늘 할 일을 적고 우선순위를 정합니다. 하루 동안 완료를 체크하고, 완료율로 진행 상황을 확인합니다.
- **사용 환경:** 데스크톱 브라우저와 모바일 브라우저.

## 3. 범위

**v1 범위:** 아래 기능 요구사항(FR)과 비기능 요구사항(NFR) 전체.

**범위 밖:** 다음은 v2 이후로 미룹니다.
- 로그인과 다중 사용자 (결정 필요: [D-01](spec-review.md#결정-필요-항목))
- 날짜별 보기(캘린더), 마감일 기준 정렬·필터, 마감 알림 (마감일 지정 자체는 FR-15로 v1에 포함)
- 정렬 변경, 검색, 태그
- 삭제 취소(undo), 오프라인 동작, 여러 탭 간 실시간 동기화

## 4. 데이터 정의

할 일(Todo) 하나는 다음 값을 가집니다.

| 필드 | 설명 | 규칙 |
| --- | --- | --- |
| `id` | 식별자 | 서버가 생성하는 UUID |
| `text` | 할 일 내용 | 앞뒤 공백을 제거한 뒤 1~200자 |
| `done` | 완료 여부 | 기본값 `false` |
| `priority` | 우선순위 | `high`(높음) / `medium`(보통) / `low`(낮음). 기본값 `medium` |
| `today` | 오늘 할 일 여부 | 기본값 `false`. 날짜가 바뀌어도 자동으로 해제되지 않음 |
| `due_date` | 마감일 | 날짜만(`YYYY-MM-DD`, 시각 없음). 선택 항목이며 기본값 `null`(마감일 없음). 지난 날짜도 지정 가능 |
| `created_at` | 생성 시각 | 서버가 기록. 목록 순서의 기준 |
| `updated_at` | 마지막 수정 시각 | 서버가 기록 |

## 5. 기능 요구사항 (FR)

| ID | 요구사항 | 상세 | 현재 구현 |
| --- | --- | --- | --- |
| FR-01 | 할 일 등록 | 내용, 우선순위, 오늘 할 일 여부를 입력해 등록합니다. Enter 또는 "추가" 버튼으로 등록합니다. 내용이 공백뿐이면 등록되지 않고 "추가" 버튼이 비활성화됩니다. 등록 후 입력창은 비워지고 포커스가 유지됩니다. | 됨 (200자 제한 없음) |
| FR-02 | 목록 조회 | 모든 할 일을 생성 순서(오래된 것 먼저)로 보여 줍니다. 각 카드에는 내용, 우선순위 배지, "오늘" 태그(해당 시)가 표시됩니다. | 됨 (메모리) |
| FR-03 | 완료 처리 | 체크박스나 내용 텍스트를 눌러 완료/미완료를 바꿉니다. 완료된 항목은 취소선과 흐린 색으로 표시하며 숨기지 않습니다. | 됨 |
| FR-04 | 수정 | "수정" 버튼으로 수정 모드에 들어가 내용, 우선순위, 오늘 할 일 여부를 바꿉니다. Enter 또는 "저장"으로 저장하고, Esc 또는 "취소"로 원래 값으로 돌아갑니다. 내용이 비어 있으면 저장할 수 없습니다. | 됨 |
| FR-05 | 삭제 | "삭제" 버튼을 누르면 확인 없이 바로 삭제됩니다. | 됨 |
| FR-06 | 우선순위 표시 | 높음/보통/낮음을 색과 텍스트를 함께 써서 표시합니다(배지, 카드 왼쪽 색 띠). | 됨 |
| FR-07 | 오늘의 작업 | "오늘 할 일"로 표시한 작업만 모아 요약 패널에 보여 줍니다. 순서는 미완료 먼저, 그다음 우선순위 높은 순, 같으면 생성 순입니다. 남은 개수를 표시하고, 패널에서도 완료를 체크할 수 있습니다. | 됨 (같은 우선순위 순서는 미정의) |
| FR-08 | 필터 탭 | 전체 / 진행 중(미완료) / 완료 탭으로 목록을 거릅니다. 각 탭에 개수를 표시합니다. 필터는 화면에서만 적용하며 서버에 저장하지 않습니다. | 됨 |
| FR-09 | 통계 카드 | 전체 작업 수, 완료 수, 미완료 수를 표시합니다. | 됨 |
| FR-10 | 완료율 | 완료 수 ÷ 전체 수를 백분율 정수(반올림)로 원형 프로그레스에 표시합니다. 할 일이 없으면 0%입니다. | 됨 |
| FR-11 | 빈 상태 | 표시할 작업이 없으면 필터별 안내 문구를 보여 줍니다. 전체 목록이 비었거나 진행 중 작업이 없으면 "할 일 추가하기" 버튼(입력창으로 포커스 이동)을 함께 보여 줍니다. | 됨 |
| FR-12 | 입력 지우기 | 새 할 일 입력창과 수정 입력창에 값이 있으면 × 버튼을 보여 주고, 누르면 값을 지우고 포커스를 입력창에 유지합니다. | 됨 |
| FR-13 | 서버 저장 | FR-01, FR-03, FR-04, FR-05의 변경을 서버(Supabase)에 저장합니다. 새로고침하거나 다른 기기에서 열어도 같은 목록이 보입니다. | **신규** |
| FR-15 | 마감일 | 등록할 때 마감일을 선택해 지정할 수 있습니다(비워 두면 없음). 수정 모드에서 마감일을 바꾸거나 지울 수 있습니다. 카드에는 마감일 배지를 보여 줍니다: 오늘이면 "오늘 마감", 내일이면 "내일 마감", 그 밖에는 "마감 11월 28일 (금)" 형식입니다. 미완료 작업의 마감일이 지났으면 "마감 지남"으로 강조합니다. "오늘"은 사용자 브라우저의 현지 날짜 기준입니다. 목록 정렬과 필터는 바뀌지 않습니다. | **신규** |
| FR-14 | 로딩과 오류 표시 | 처음 목록을 불러오는 동안 로딩 상태를 보여 줍니다. 서버 요청이 실패하면 무엇이 실패했는지와 다시 시도하는 방법을 보여 주고, 화면 데이터는 서버 상태와 어긋나지 않게 유지합니다. | **신규** |

## 6. 비기능 요구사항 (NFR)

| ID | 요구사항 | 상세 |
| --- | --- | --- |
| NFR-01 | 반응형 | 880px 초과는 2열(왼쪽 요약, 오른쪽 입력·목록), 이하는 1열(입력 → 요약 → 목록)로 배치합니다. 390px에서 가로 스크롤이 없어야 합니다. |
| NFR-02 | 키보드 접근성 | 모든 기능을 키보드만으로 쓸 수 있어야 합니다. 키보드 포커스가 눈에 띄게 표시됩니다. 삭제 후에는 입력창으로, 수정 저장·취소 후에는 "수정" 버튼으로 포커스가 이동합니다. 필터 탭은 ←/→/Home/End로 이동합니다. |
| NFR-03 | 스크린 리더 | 모든 입력과 버튼에 라벨이 있습니다. 목록 버튼 라벨에는 작업 이름이 들어갑니다. 완료율은 progressbar 역할과 값을 제공합니다. |
| NFR-04 | 디자인 일관성 | [ui-guidelines.md](ui-guidelines.md)를 따릅니다. 외부 UI 라이브러리를 쓰지 않습니다. |
| NFR-05 | 보안 | Supabase 키는 백엔드 환경 변수에만 둡니다. 프론트엔드는 Supabase에 직접 접근하지 않습니다. 직접 접근하지 못하도록 DB에 RLS를 켭니다. |
| NFR-06 | 배포 | 프론트엔드와 API를 Vercel에 배포합니다. 환경 변수는 Vercel 설정으로 주입합니다. |
| NFR-07 | 응답성 | 일반 요청(목록 조회, 등록, 수정, 삭제)은 서버 응답 1초 이내를 목표로 합니다. 응답을 기다리는 동안 같은 버튼을 다시 누를 수 없습니다. |
